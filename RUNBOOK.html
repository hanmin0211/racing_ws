빌드 확인

출발 전 · 노트북만 있으면 됨

현장에서 빌드 오류를 처음 보는 일이 없게 한다.

cd ~/racing_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select mission_perception gps_localization velocity_controller
source install/setup.bash

원점이 대구인지 확인

grep -E "^(site|utm_epsg|origin_x|origin_y):" ~/racing_ws/config/site_origin.yaml

네 줄이 이렇게 나와야 한다:

site: "대구권 시험장 (2026-08-17 측정)"
utm_epsg: 32652
origin_x: 477800.0
origin_y: 3964400.0

원점이 틀리면 오차가 아니라 150km 어긋난다. 2026-08-17 에 실제로 발생했다. 다른 건 다 맞아도 이거 하나면 전부 무의미하다.

통과 조건 — 빌드 에러 0개, 원점이 대구 값.

1

후진 벤치 검증

차 연결 후 · 바퀴 공중 · 5분

후진이 물리적으로 되는지 숫자로 확정한다. 이게 안 되면 아래가 전부 무의미하다. 후진은 아직 실차에서 한 번도 안 돌려봤다.

바퀴를 공중에 띄울 것. 개루프 구동이라 차가 그대로 튀어나간다. ROS 스택은 꺼둔다 — serial_bridge 가 포트를 잡고 있으면 안 열린다.

bash ~/racing_ws/tools/ros_cleanup.sh
python3 ~/racing_ws/tools/reverse_bench.py

스크립트가 전진 기준선을 먼저 잰 뒤 후진을 걸고, 세 가지를 자동 판정한다.

측정정상틀리면
엔코더 부호전진↔후진 반대 counts_per_revolution 부호 / 배선
속도 계산후진 = 음수 NO_ENCODER / SPI 카운터 CS22·23
후진 중 조향좌우 ADC 반대로 조향핀 A15 / 데드밴드 / 캘리브

조향이 반대로 나오면 코드를 고치지 말 것. 실행할 때 -p steer_sign_reverse:=-1.0 만 주면 된다. 기본값 +1.0 은 자전거모델 유도와 시뮬로 확인한 값이다 (뒤집으면 시뮬에서 1m 이탈).

통과 조건 — 세 항목 모두 ✅. 하나라도 ❌ 면 여기서 멈춘다. 부분 실패인 채로 현장 기록에 들어가면 찍은 궤적이 전부 쓸모없어진다.

2

RTK 품질 확보

대회장 도착 후 · 좌표 찍기 전

Fixed 가 아닌 상태에서 찍은 좌표는 수십cm~m 씩 틀린다. 64cm 규정에서 그건 곧 실격이다.

# 터미널1 — GPS + NTRIP + 측위
ros2 launch gps_localization bringup.launch.py control:=true rviz:=true
# 터미널2 — RTK 품질 감시
python3 ~/racing_ws/tools/gps_check.py
수평 σ등급판단
≤ 5cmFIXED기록 가능
≤ 50cmFLOAT기록하면 경로가 흔들린다 — 기다린다
> 50cm단독측위NTRIP·안테나부터 확인

status 값으로 판정하지 말 것. 지금 드라이버는 Fixed 에서도 status=1 만 내보낸다. 공분산(σ)으로만 판정한다.

통과 조건 — σ ≤ 5cm 가 안정적으로 유지. 수신율 10Hz.

3

코스 + 정지선 — 한 번에

출발지점부터 한 바퀴

경로와 정지선을 같은 주행에서 딴다. 정지선에서 5초 서기만 하면 자동으로 잡힌다 — 엔터도, 두 번째 랩도 필요 없다.

teleop — 반드시 이걸 쓸 것

ros2 run velocity_controller teleop_keyboard

wasd_teleop 를 쓰면 안 된다. 그건 /cmd_vel 에 직접 쏴서 먹스를 우회한다 — E-stop 도 안 듣는다. teleop_keyboard 만 /teleop/cmd_vel 로 나간다.

키동작
W / S전진 / 후진 — 누르고 있는 동안만 (데드맨)
A / D조향 좌 / 우 — 각도 유지, 스텝 2°
SPACE정지 + 조향 중앙
E비상정지 토글
Q / Z목표 속도 증감

레코더 둘을 같이 켠다

# 터미널 A — 경로
ros2 run waypoint_follower waypoint_recorder
# 터미널 B — 정지선 (서 있기만 하면 자동)
ros2 run mission_perception stop_detector
  1. 출발지점에서 시작
  2. 코스를 한 바퀴 돈다
  3. 정지선에서 5초 정지 — 그냥 서 있으면 된다
  4. 계속 돌아 완주 후 Ctrl-C (양쪽 다)

왜 감지기가 따로 필요한가 — 경로 레코더는 이동거리로 점을 찍는다. 서 있는 동안은 점이 안 찍히므로, 경로 파일만 봐서는 어디서 섰는지 알 수 없다. 시간을 보는 눈이 따로 있어야 한다.

감지기는 출발 전 대기를 무시하고(3m 주행 후부터 셈), 같은 자리 중복도 거른다. 감지 즉시 저장하므로 Ctrl-C 가 씹혀도 남는다.

마지막 정지는 확인할 것. 기록을 끝내며 선 자리도 정지로 잡힌다. Ctrl-C 하면 번호별 목록이 뜨고 마지막 것에 표시가 붙는다 — 실제 정지선이 아니면 ~/stop_points.yaml 에서 그 항목을 지운다.

확인

런치를 다시 띄웠을 때 [bringup] 정지지점 N개 로드 가 떠야 한다. 경로에서 멀다 가 뜨면 옛 충주 파일이 남은 것이다.

차는 찍은 지점보다 약 33cm 앞에서 선다. 제어가 0.3m 이하에서 하드정지하기 때문이다. 규정 64cm 안이라 그대로 두면 된다. 더 붙이려면 stop_bias 를 양수로 준다.

통과 조건 — 경로 yaml 저장됨 + 정지지점 목록에 실제 정지선이 잡혀 있음.

4

주차 3자리

어느 자리가 지정될지 모르므로 3곳 다

좁은 칸에 후진으로 넣으며 기록하지 않는다 — 급하게 꺾인 궤적은 최소회전반경(2.42m)을 넘어 재생 때 못 따라간다. 아래 두 방법 다 그 문제를 피한다.

A. 자세만 찍기B. 나오면서 찍기
운전없음 — 손으로 놓음전진으로 나오기만
소요1분3분
경로계산된 원호실제로 지나간 길
장애물모름반영됨

칸 주변에 라바콘·다른 차가 있으면 B, 뻥 뚫려 있으면 A 가 빠르다.

A. 차를 칸에 넣어두고 자세만 찍기

ros2 run mission_perception parking_pose_recorder --ros-args -p slot:=1
# 흔들림이 10cm 아래일 때 Enter

python3 ~/racing_ws/tools/make_parking_path.py --slot 1 --plot

구루마로 밀든 손으로 넣든 상관없다. 최종 자세만 맞으면 된다. 진입 궤적은 반경 2.8m 로 고정해 생성하므로 실현 가능성이 설계상 보장된다. 접근 헤딩은 트랙에서 자동으로 가져온다.

B. 칸에서 전진으로 나오며 찍고 뒤집기

ros2 run mission_perception parking_recorder --ros-args \
    -p slot:=1 -p output:=~/parking_exit_1.yaml
# 칸 안에서 시작 → 전진으로 커브 → 트랙 위 2~3m 더 → Ctrl-C

python3 ~/racing_ws/tools/make_parking_path.py --slot 1 \
    --from-exit ~/parking_exit_1.yaml --plot

왜 뒤집어도 되나 — 후진으로 들어가는 건 어렵지만 전진으로 나오는 건 쉽다. 나올 때 지나간 자리를 거꾸로 되짚으면 그게 곧 들어가는 길이고, 곡률이 같으니 실현 가능성도 그대로다. 헤딩도 맞는다: 나올 때 점 P 에서 차가 출구 쪽을 봤다면, 들어갈 때 같은 점에서 차는 칸 쪽으로 후진하므로 헤딩은 여전히 출구 쪽이다.

나올 때 너무 급하게 꺾지 말 것. 2.42m 를 넘으면 곡률 검사에 ❌ 못 도는 구간 이 뜨고, 더 크게 돌아 다시 찍어야 한다.

어느 쪽이든 찍은 즉시 검증 — 자리당 30초

python3 ~/racing_ws/tools/test_parking_node.py --file ~/parking_1.yaml
  • 생성 단계에서 곡률 검사 ✅ 실현 가능 였는가
  • 생성 단계에서 접근 시작점이 트랙에서 ✅ 였는가
  • 재생에서 DONE + 오차 30cm 이내인가

ABORT 나 못 도는 구간 이 뜨면 그 자리는 다시 한다. 본 주행에서 터지는 것보다 지금 3분 더 쓰는 게 싸다.

통과 조건 — ~/parking_1.yaml, parking_2, parking_3 세 개 모두 DONE + 오차 30cm 이내.

5

본 주행

지정 자리를 통보받은 뒤

완주 → 횡단보도 정지 → 후진주차.

지정받은 자리 번호를 parking_slot 에 넣는다 — 바꿀 건 이것뿐

bash ~/racing_ws/tools/ros_cleanup.sh

# 터미널1 — 주행
ros2 launch gps_localization bringup.launch.py \
    control:=true auto_calib:=true rviz:=false max_speed:=1.0 \
    crosswalk:=true parking:=true parking_slot:=1
# 터미널2 — 로그 (반드시 같이 켤 것)
python3 ~/racing_ws/tools/drive_log.py

mission:=true 를 같이 주지 말 것. 신호등 노드와 횡단보도 노드가 둘 다 /stop_line_distance 를 발행해 서로 덮어쓴다. 둘 중 하나만.

진행 순서

  1. 헤딩 캘리브 — 10m 직진. 앞을 비우고 E-stop 을 쥔다
  2. 완주 — 횡단보도는 자동이다 (정지 → 3초 → 재출발)
  3. 주차 접근점 도달 — 여기서 사람이 트리거한다
ros2 topic pub --once /parking/start std_msgs/Bool "{data: true}"

자리를 바꿔야 하면 시작 전에:

ros2 topic pub --once /parking/select std_msgs/Int32 "{data: 2}"

상태 확인

ros2 topic echo /parking/state      # WAIT→DRIVE→CUSP→DONE
ros2 topic echo /crosswalk/state    # IDLE→APPROACH→HOLD→CLEARED

주차 노드는 끝난 뒤에도 0 을 계속 발행한다. 정상이다 — 발행을 멈추면 0.5초 뒤 먹스 데드맨이 풀려 차가 자율로 다시 출발한다.

터졌을 때

증상원인 / 조치
차가 안 움직임 헤딩 캘리브 전이면 먹스가 AUTO 를 거부한다. 로그에 STOP(헤딩 캘리브 전) 확인
주차가 ABORT 궤적 1m 이탈 또는 헤딩 이상. 로그에 이유가 찍힌다. RTK 가 Float 로 떨어졌는지 먼저 본다
주차가 시작 안 됨 궤적 시작점에서 3m 넘게 떨어져 있으면 거부한다. 접근점까지 몰고 가서 다시 트리거
횡단보도에서 안 섬 /stop_line_distance 발행자가 2개인지 확인 (mission 과 crosswalk 동시 실행)
3초 후 출발 안 함 차가 완전히 안 멈춰서 타이머가 시작 안 된 것. 8초 뒤 자동 통과하며 경고가 찍힌다
정지선을 지나침 stop_bias 를 음수로 (더 일찍 서게)
VMIN 경고 3893mV 무시해도 된다. 3.9~4.1V 가 이 차의 정상대다

E-stop 은 항상 손에. 모든 실차 단계에서. teleop 의 E 키가 먹스의 최상위 우선순위다.

검증 상태 — 후진주차·횡단보도 노드는 시뮬 폐루프로만 검증됐다 (주차 오차 22cm / 정지 33cm · 3.1초). 실차 미검증. 조향 극성은 1단계 벤치 측정으로 확정할 것.
